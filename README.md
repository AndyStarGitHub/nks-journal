# Specialist Journal

Модуль **Specialist Journal** — це кастомний модуль для Odoo, який дозволяє спеціалістам вести журнал роботи з клієнтами безпосередньо в картці контакту, використовуючи шаблони записів та контроль доступу за ролями.

---

## 🔧 Сумісність

* **Odoo**: 19.0
* **Залежності**: `base`, `contacts`

---

## 🎯 Основна ідея

Кожен спеціаліст може:

* створювати записи журналу по клієнтах;
* бачити записи інших спеціалістів по цьому ж клієнту;
* редагувати **тільки свої** записи;
* використовувати заздалегідь створені шаблони для швидкого заповнення нотаток.

Адміністратор може:

* переглядати всі записи;
* створювати та редагувати шаблони.

---

## 👥 Ролі та доступи

### Specialist Journal: User

* перегляд усіх записів по клієнтах;
* створення нових записів;
* редагування та видалення **лише власних** записів;
* використання шаблонів (тільки читання).

### Specialist Journal: Admin

* перегляд усіх записів;
* створення / редагування / видалення шаблонів;
* **не може** редагувати чужі записи журналу (тільки читання).

Контроль доступу реалізований через:

* `ir.model.access.csv`;
* record rules.

---

## 🧾 Journal Entries (Записи журналу)

Модель: `specialist.journal.entry`

Основні поля:

* **Client** (`partner_id`)
* **Specialist** (`user_id`)
* **Date** (`date`)
* **Type** (`entry_type`)
* **Title** (`name`)
* **Notes** (`content`)

Записи доступні:

* з головного меню **Specialist Journal → Entries**;
* безпосередньо в картці клієнта (вкладка *Specialist Journal*).

---

## 🧩 Шаблони записів

Модель: `specialist.journal.template`

Поля:

* **Name** — назва шаблону;
* **Default Type** — тип запису (обмежений enum);
* **Body** — текст шаблону.

### Використання шаблонів

У формі створення запису:

* спеціаліст може обрати **один або кілька шаблонів**;
* кнопка **Apply Templates** вставляє тексти шаблонів у поле *Notes*;
* текст **додається**, а не перезаписується.

Це зроблено навмисно для максимально передбачуваної поведінки.

---

## 🖨️ PDF-друк (бонус)

Реалізовано PDF-звіт:

* **всі записи по клієнту**.

### Як працює:

* у картці клієнта доступна кнопка **Print Journal PDF**;
* формується PDF з:

  * назвою клієнта;
  * усіма записами журналу (дата, спеціаліст, тип, заголовок, нотатки).

---

## 🧪 Demo-дані

Модуль містить **demo-дані**, які створюються **тільки якщо база створена з demo**.

### Demo включає:

* тестових користувачів (спеціалісти);
* тестових клієнтів;
* приклади шаблонів;
* приклади записів журналу.

Це зручно для:

* швидкого ознайомлення;
* демо;
* перевірки функціоналу після встановлення.

## 📦 Встановлення

1. Скопіювати модуль у `addons` або `extra-addons`.
2. Оновити список модулів.
3. Встановити **Specialist Journal**.
4. (Опційно) створити базу з demo-даними.

## 🚀 Як запустити модуль (для тих, хто не працював з Odoo)

### Вимоги

* Docker + Docker Compose
* Git

### Кроки запуску

1. **Клонувати репозиторій**

   ```bash
   git clone https://github.com/AndyStarGitHub/nks-journal.git
   cd nks-journal
   ```

2. **Запустити контейнери**

   ```bash
   docker compose up -d
   ```

3. **Відкрити Odoo в браузері**

   ```text
   http://localhost:8069
   ```

4. **Створити нову базу**

   * Увімкнути прапорець **Load demonstration data** (важливо)
   * Саме в цьому випадку автоматично створяться:

     * demo-користувачі
     * demo-клієнти
     * demo-шаблони журналу
     * demo-записи журналу

5. **Увійти під demo-користувачем**

   * Логіни / ролі описані нижче в розділі *Demo-дані*

## ⏱️ Обмеження на редагування записів журналу

За замовчуванням діє таке правило:

* **Спеціаліст може редагувати лише власні записи**
* **Редагування можливе тільки протягом обмеженого часу після створення запису**

### Налаштування часу редагування

Обмеження задається через системний параметр:

```text
specialist_journal.edit_window_hours
```

* Значення — кількість годин після створення запису
* Приклад: `4` → редагування дозволено протягом 4 годин
* Значення `0` або відсутній параметр → **без обмеження по часу**

Параметр можна змінити через:

* **Settings → Technical → Parameters → System Parameters**

Після завершення цього часу:

* запис залишається доступним для перегляду
* будь-які зміни будуть заблоковані з повідомленням про помилку доступу
